# Upgrading from <=1.5.1

> This is a **one-time migration**. Nodes already running v1.5.2 or later do not need it: to update such a node, stop it, run `git pull` and `npm i`, then start it again (see `scripts/start.sh` and [syncing-your-node.md](./syncing-your-node.md)).

From Avalon v1.5.2 onwards, blocks data are appended to and read from a file called `blocks.bson`, which is also the mongo dump file obtained using `mongodump`. This is to take load off the main MongoDB database which results in decreased RAM usage and increased indexing efficiency.

To upgrade your node (assuming Avalon is not running):

1. Run a `git pull`. Resolve conflicts for the `scripts/start.sh` file if required.
2. Install latest node dependencies.
```
npm i
```
3. Create the dump file for blocks collection.
```
mongodump -d avalon -c blocks
```
4. Drop the blocks collection from the mongo database.
```
mongosh avalon --eval "db.blocks.drop()"
```
5. Specify the full path to the folder containing the `blocks.bson` file with the `BLOCKS_DIR` env var, which may also be found in the `scripts/start.sh` script.
6. Restart `mongod` to realize RAM usage savings.
7. Start Avalon. It should create a file called `blocks.index` which contains the pointers of each block to the `blocks.bson` file (each block takes up exactly 8 bytes of indexing). This may take some time to complete.

The `blocks.metadata.json` file generated from `mongodump` is not required by Avalon in normal operation, and can be deleted safely. Only the full chain rebuild flow (which restores from a `dump/` folder) reads it back.

## Transaction history

Transaction history is indexed separately with the `TX_HISTORY` env var (`TX_HISTORY=1`). If the `/tx` and `/history` APIs are needed, a full rebuild is required to create the indexes. Use `TX_HISTORY_ACCOUNTS` to restrict indexing to a comma-separated list of accounts (transactions where the account is sender, target, receiver, parent author or author); leave it unset to index the whole chain.
